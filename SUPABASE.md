# Shared leaderboard setup

The app uses Supabase's browser REST API so the leaderboard is shared between
visitors and devices. No service-role key belongs in this repository.

1. Create a Supabase project and copy its **Project URL** and **anon public**
   key into `supabase-config.js`.
2. In the Supabase SQL editor, run:

   ```sql
   create table public.leaderboard (
     id bigint generated by default as identity primary key,
     date date not null,
     name text not null check (char_length(name) between 1 and 20),
     score integer not null check (score >= 0),
     words integer not null check (words >= 0),
     pangram boolean not null default false,
     created_at timestamptz not null default now()
   );

   create index leaderboard_date_score_idx
     on public.leaderboard (date, score desc, created_at asc);

   alter table public.leaderboard enable row level security;

   create policy "Anyone can view leaderboard scores"
     on public.leaderboard for select
     to anon using (true);

   create policy "Anyone can submit leaderboard scores"
     on public.leaderboard for insert
     to anon with check (true);
   ```

3. Deploy the site. Existing `leaderboard.txt` entries remain useful as starter
   scores, and the app falls back to local storage if Supabase is not configured.

The score is submitted by the browser, so this is suitable for a casual
leaderboard, not a cheat-resistant competitive ranking. A trusted server or
authenticated submission flow is needed if scores must be verified.
